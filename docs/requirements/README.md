These are review drafts on feature branches. A requirements entry is a target, not a claim that a capability is implemented, secure, released or available for subscription. Existing project authorization and release gates remain in force.

The requirements workflow uses stable IDs, independent feature versions, acceptance cases, declared dependencies, append-only historical snapshots and integrity checks against the target branch. Git/CI administrators remain in the trust model; this is tamper-evident tracking rather than administrator-proof immutability.

The coordinated delivery approach defines shared contracts first, develops frontend/backend modules in parallel, and integrates bounded end-to-end workflows with independent evidence before acceptance. Sensitive implementation and operational details are not mirrored into this public index.
